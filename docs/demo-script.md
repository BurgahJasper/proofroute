# Demo scripts

All messages are synthetic. The Figma listing, when the check is live, is public board data. Do not accuse a real recruiter.

## 30-second cut

1. Open the labeled Avery Chen sample that cites requisition 6143238004.
2. Review it and run a live check.
3. Show the supported listing and the unresolved sender line: "This does not verify the sender."
4. Open the official application link from the employer-linked board.

| Time | On screen | Say |
|---|---|---|
| 0–10s | Labeled synthetic offer for the public intern role | Would you trust this because the job exists? |
| 10–30s | Review, then the activity list during a live check | ProofRoute reads the employer-linked board. It does not trust the message's instructions. |
| 30–48s | Listing evidence, then the dashed sender row | The role is published. The sender is not confirmed. |
| 48–70s | Sample follow-up asking for an equipment payment and a login code | The listing stays supported. The next step changes to pause. |
| 70–87s | Official application link and Markdown export | Use the board's application route. Nothing is emailed for you. |
| 87–102s | Benign agency sample or a fixture/partial state | An unfamiliar note without a sensitive request is not called fraud. |
| 102–115s | Evaluation summary | Live product path: 24 of 24 recommendation labels matched. Team-created prompt-only baseline: 17 of 24. The other 7 are official-route mismatches, not API failures and not a scam-detection score. |

If the network fails, turn on fixture replay and say that the badge means captured public data, not a live read.
